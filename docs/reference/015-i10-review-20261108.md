## Remaining release blockers

1. **Writer ownership after timeout/rebalance is still uncertain.**
   libs/py-common/py_common/storage/parquet.py write_dataframe overwrites canonical
   bytes after reading/merging them; registration occurs after the upload. There is
   no storage-level compare-and-swap or immutable version addressability in this
   path. apps/ingestor/app/handlers/stock_prices.py merges its earlier existing_df
   and writes the full symbol file. A delayed writer overlapping a replacement
   attempt can overwrite newer rows even though Platform rejects its late status
   or registration. ExecutionTimeoutWatchdog explicitly reports UNCERTAIN rather
   than proving worker termination. This is an existing ADR-008 cutover blocker,
   not a new polling defect; this delivery does not implement deferred P12 writer
   recovery, fencing, batching or concurrency activation. Preserve the exclusive
   drained-writer window and require proven write exclusion/version safety before
   general cutover. Regression needed for release: stale worker resumes after
   timeout/rebalance while a replacement writes, with physical bytes preserved.

2. **Full attributable coverage is incomplete.** The new graph lookup helper has
   71.88% branch coverage, below the default 80%; the earlier WorkExpansion policy
   report was 78.98% branch. Broad project passes cannot erase these gaps. The new
   polling service exceeds both thresholds, but that is not whole-I10 acceptance.

3. **Coordinated rollout/parity/recovery evidence remains open.** Selected worker
   E2E tests use a stubbed market provider and disposable Kafka/PostgreSQL/MinIO.
   They establish the tested chain, not retained production reader parity,
   provider behavior, replay/rebalance safety or global legacy cutover. Contracts
   tooling was reported repaired by the owner; historical protoc failure is not
   a current blocker claim. Contract generation was not rerun in this delivery.
