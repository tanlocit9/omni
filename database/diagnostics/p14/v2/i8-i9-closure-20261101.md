### Retained-data rollout and rollback rehearsal

`retainedDataRolloutRehearsalDrainsGraphAndRestoresLegacyWithoutRewritingHistory`
uses a real disposable PostgreSQL application. It creates graph-disabled V1 work,
retains terminal historical rows, restarts with graph enabled, consolidates actual
seeded definitions and prepares a 100-symbol catalog into 201 atomic attempts.
The measured preparation is approximately four seconds, below its 120-second
transaction budget. This is a bounded sample, not a retained-production capacity claim.
Replay creates no extra attempts. Bounded reconciliation drains the work, actual
consolidation rollback restores scheduling, and another graph-disabled restart
creates new V1 work while the old V1 snapshot stays byte-for-byte identical.

The rehearsal seeds terminal child outcomes to isolate control-plane migration,
drain and rollback. It does not stand in for computation or Kafka completion;
the four independent worker workflows cover those. The V16-to-V18 migration test
separately proves historical FK/offset/frozen-path preservation and Flyway validation.
No production catalog is measured or modified. Before activation, run the documented
retained-environment inventory/capacity/drain procedure with matching deployments.
