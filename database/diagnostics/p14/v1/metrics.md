# Scheduler observation dictionary v1

This is P14-I5's semantic handoff for I6 and [Plan 029](../../../../docs/plans/029-operator-trust-console.md),
not a new endpoint, exporter, metrics table or accepted UI contract. PostgreSQL
and the existing guard remain authoritative. Unknown/unavailable observations are
null with a reason, never numeric zero or a fabricated processing state.

| Field / measure                                           | Unit / source                                           | Meaning and limitation                                                                                                                                                                                                               |
| --------------------------------------------------------- | ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| version, observedAt, complete, reason                     | v1 SQL envelope / UTC instant / boolean / bounded code  | Completeness concerns the explicit requested window. observedAt is a caller observation clock; capture duration and age are separate.                                                                                                |
| run identity, step, effective scope/date                  | PostgreSQL frozen instance                              | Detail/filter dimensions only. Never replace run UUID with businessGroup/date and never put UUIDs, symbols or scope keys in unbounded metric labels.                                                                                 |
| closed, child_count, message_count, roots, executions     | V13 preparation and separate scoped aggregates          | Expected versus observed immutable membership. Parent is one execution; executions normally equals child_count+1. Message count is not execution count.                                                                              |
| progress / failed / unknown_executions / identities_match | persisted execution and closure evidence                | SUCCESS needs all closed members successful; FAILED_OR_BLOCKED and UNKNOWN_MEMBERSHIP cannot open a barrier. No worker state is inferred from queue publication.                                                                     |
| ancestor_count / predecessor_wait                         | frozen predecessor closure and persisted progress       | All required ancestors, including joins; intermediate SUCCESS cannot conceal an unfinished earlier step. Does not evaluate dataset readiness.                                                                                        |
| eligible / leased / retry_delayed / blocked               | outbox status, availability and lease at observedAt     | Distinct current PENDING classifications, not publish attempts or worker activity. BLOCKED is terminal dependency rejection, not a provider FAILED result.                                                                           |
| published / published_but_unfinished                      | outbox broker acknowledgement versus execution progress | PUBLISHED alone proves neither successful execution nor READY. Counts are not actual provider throughput or active worker count.                                                                                                     |
| identity_state / counts / live_lease                      | legacy inventory page                                   | Bounded page classification only; malformed data is UNKNOWN/conflict. A normal FK/payload does not by itself prove safe business semantics.                                                                                          |
| hasMore / nextCursor / rowLimit                           | inventory UUID keyset page                              | The cursor is a scan continuation, not an authoritative migration checkpoint. Global counts require reconciled snapshots/quiescence; concurrent paging has limitations.                                                              |
| snapshot/planner/scoped-query/claim duration              | milliseconds, measured monotonic elapsed samples        | Report warmups, sample counts and p50/p95/p99 using nearest-rank percentiles, plus workload/environment. Transaction timing includes its declared completion/rollback boundary. Never substitute query cost estimates for wall time. |
| rows / loops / shared buffers / scan and index nodes      | PostgreSQL EXPLAIN ANALYZE BUFFERS JSON                 | Per-query observation with exact source/parameters. Cached/uncached runs differ; index choice and output bounds alone do not establish production performance.                                                                       |
| JDBC execute calls / transaction boundaries               | test-only statement/connection instrumentation          | Application-level SQL execution calls and commit/rollback calls; not TCP packets or PostgreSQL wire-message counts. State the observation boundary rather than claiming exact network round trips.                                   |
| Hikari active / idle / total / waiting / acquisition wait | pool MXBean and measured connection acquisition         | Per-sample gauge and observed maximum; acquisition wait includes checkout overhead. An absent pool metric is unavailable, not a zero-pressure pass.                                                                                  |
| planned / selected / claimed / published / executed       | explicit harness/tick event counters                    | Keep allocation, read candidate, successful fenced claim, broker ack and actual status separate. Synthetic applyStatus completion is not a measured provider/worker execution.                                                       |
| publish/status throughput                                 | events per measured second over a declared window       | Disposable fake-broker/status-fixture throughput must be labelled synthetic. Real worker throughput requires actual worker timing evidence under P13-I1; preparation-time RUNNING is insufficient.                                   |
| comparison / unavailable reason                           | same workload reference and environment                 | Compare baseline/reference and current samples without invented PASS thresholds. Optional pg_stat_statements, real network/provider timings and uncollected metrics remain explicitly unavailable.                                   |

Bounded metric labels may use stage, planner mode, outcome/reason category and a
fixed benchmark scenario. Identifiers and raw payloads belong only in access-
controlled bounded detail reports. No ETA, SLA, real worker start timestamp,
dataset readiness, immutable dataVersion or lineage is inferred by this dictionary.
